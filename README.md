# Facebook Messenger AI бот — тусгай зөвшөөрлийн хүсэлт авах

Пэйж рүү бичсэн хүнтэй Claude 24/7 харилцана. Бот хоёрхон зүйл асууна:
1. Ямар чиглэлийн эмнэлгийн тусгай зөвшөөрөл авах сонирхолтой байгааг.
2. Утасны дугаарыг нь.

Хэрэглэгч дугаараа бичмэгц танд Telegram-аар **«📞 Шинэ хүсэлт»** мэдэгдэл очно. Мэдэгдэлд сонирхож буй чиглэл болон утасны дугаар байна. Дараа нь ажилтан залгаж ярина.

```
Хэрэглэгч → Messenger → Meta webhook → Vercel (/api/webhook)
                                          ├─ гарын үсэг шалгана (META_APP_SECRET)
                                          ├─ 200-г шууд буцаана
                                          └─ дараа нь: утасны дугаар таних (код) → яриан түүх → Claude → хариулт
                                                                    └─ дугаар байвал → Telegram «📞 Шинэ хүсэлт»
Vercel Cron (өдөр бүр 09:00) → /api/health → token, webhook, Telegram шалгана → асуудал байвал Telegram
```

## Ботын дүрэм
- Зөвхөн чиглэл болон утасны дугаар асууна. Нэр, регистр, хаяг, имэйл асуухгүй.
- Танай хаяг, утасны дугаарыг өгөхгүй. Үнэ, хугацаа, бүрдүүлэх бичиг баримт, шаардлагын талаар тайлбар хийхгүй, «мэргэжилтэн утсаар тайлбарлана» гэж хариулна.
- **Утасны дугаарыг AI биш, код таньдаг.** 5–9-өөр эхэлсэн 8 оронтой тоог дугаар гэж үзнэ. Урдаа +976 байж, хооронд нь зай, зураас, цэг тавьж болно. Буруу бичвэл бот дугаараа дахин шалгаж бичихийг хүснэ.
- AI ажиллахгүй байсан ч утасны дугаар Telegram-д очно. Messenger-ийн хариулт илгээгдээгүй байсан ч мөн адил.
- Telegram руу хоёр удаа илгээхийг оролдоно. Хоёулаа бүтэлгүйтвэл мэдэгдлийг Vercel → **Logs** хэсэгт бичнэ. Бүх яриа пэйжийн Messenger inbox-д ч хадгалагдана.
- Гомдол болон яаралтай хүсэлтийг ажилтанд мэдэгдэнэ. Амь насанд аюултай нөхцөлд 103, 102 руу залгахыг зөвлөнө.
- «Хүн үү?» гэж асуувал AI гэдгээ хэлнэ. Картын дугаар, нууц үг асуухгүй.

## Тохируулах алхмууд

### 1. Мэдлэгийн сан (бэлэн)
`lib/knowledge.ts` бөглөгдсөн байгаа. Танай үйлчилгээг ерөнхийд нь тайлбарлаж, Messenger-ээр юу өгөхгүйг заасан. Засах бол энэ файлыг, эсвэл Vercel env-ийн `BUSINESS_KNOWLEDGE`-ийг өөрчилнө.

### 2. Meta апп үүсгэх
1. developers.facebook.com → **My Apps → Create App**
2. Use case: **Engage with customers on Messenger from Meta**, эсвэл Messenger-тэй холбоотой use case
3. Business portfolio-оо холбоно
4. **App settings → Basic** хэсгээс **App ID** болон **App Secret**-ийг хуулж авна. Privacy Policy URL шаардвал энгийн нэг хуудас тавина.

### 3. Claude API түлхүүр
platform.claude.com → **API Keys → Create key**. **Billing → Spend limit** дээр сарын дээд хязгаар тавиарай. Эхлээд $10 хангалттай.

### 4. Telegram мэдэгдэл (ЗААВАЛ)
Утасны дугаарууд зөвхөн Telegram-аар ирдэг. Энэ тохиргоо дутуу бол бот асахгүй.
- Telegram дээр @BotFather → `/newbot` → гарсан token-ыг `TELEGRAM_BOT_TOKEN`-д хийнэ
- Шинэ ботдоо нэг мессеж бичнэ. Дараа нь @userinfobot-оос өөрийн ID-г авч `TELEGRAM_CHAT_ID`-д хийнэ.
- Хэд хэдэн ажилтан мэдэгдэл авах бол Telegram групп үүсгээд ботоо нэмнэ. Группын ID (`-100…` гэж эхэлдэг) -г `TELEGRAM_CHAT_ID`-д хийнэ.

### 5. Vercel-д байршуулах
1. Энэ код GitHub-ийн private repo-д байна
2. vercel.com → **Add New → Project** → тэр repo-г сонгоно
3. **Environment Variables**-д `.env.example` доторх утгуудыг оруулна. `PAGE_ID` болон `PAGE_ACCESS_TOKEN`-ыг 7-р алхмын дараа нэмнэ. Тэр болтол бот ажиллахгүй, энэ нь хэвийн.
   - `WEBHOOK_VERIFY_TOKEN`, `CRON_SECRET`: санамсаргүй урт текст байна. Жишээ нь `openssl rand -hex 24`.
4. Deploy хийнэ. Хаяг нь `https://<нэр>.vercel.app` хэлбэртэй гарна.

### 6. Webhook холбох
Meta апп → **Messenger → Messenger API Settings → Configure webhooks**
- Callback URL: `https://<нэр>.vercel.app/api/webhook`
- Verify token: `WEBHOOK_VERIFY_TOKEN`-той яг ижил утга
- Subscription fields: **messages**, **messaging_postbacks**

### 7. Page token авах
1. developers.facebook.com/tools/explorer → өөрийн аппаа сонгоно
2. **Get User Access Token** дарж дараах эрхүүдийг сонгоно: `pages_show_list`, `pages_messaging`, `pages_manage_metadata`, `pages_read_engagement`, `business_management`
3. Гарсан token-ыг хуулж, өөрийн компьютер дээр ажиллуулна:
   ```bash
   META_APP_ID=... META_APP_SECRET=... USER_TOKEN=... node scripts/get-page-token.mjs <PAGE_ID>
   ```
   Скрипт урт хугацааны token гаргаж, пэйжийг webhook-д бүртгээд `PAGE_ID` болон `PAGE_ACCESS_TOKEN`-ыг хэвлэнэ.
4. Тэдгээрийг Vercel env-д нэмээд **Redeploy** хийнэ.

### 8. Турших
1. **Өөрийн бүртгэлээс** пэйж рүү «Сайн байна уу» гэж бичнэ. Бот ямар чиглэлийн зөвшөөрөл сонирхож байгааг асуух ёстой.
2. Чиглэлээ хэлнэ, жишээ нь «шүдний эмнэлэг». Бот утасны дугаар асуух ёстой.
3. `9911 2233` гэж бичнэ. Бот талархаж, ажилтан залгана гэж хариулах ёстой. Telegram-д «📞 Шинэ хүсэлт» ирэх ёстой.
4. `991122` гэж буруу дугаар бичнэ. Бот дугаараа дахин шалгаж бичихийг хүсэх ёстой.
5. **Аппад ямар ч эрхгүй найзын бүртгэлээс** бичнэ. ⚠️ Энэ бол хамгийн чухал тест (доорх хязгаарлалтыг үзнэ үү).

## Ботыг унтраах
Vercel env-д `BOT_ENABLED=false` болгоод Redeploy хийнэ. Мессеж ирсээр байх ч бот хариулахгүй, та гараар хариулна.

## Мэдэгдэж буй хязгаарлалт
- **Олон нийтэд хариулах эрх (баталгаажуулах шаардлагатай).** Meta-гийн баримт бичигт өөрийн пэйжийн мессежинд App Review шаардлагагүй гэж бичсэн. Гэхдээ Standard Access нь аппад эрхтэй хүмүүсээр хязгаарлагддаг гэж бас бичсэн. Тиймээс эрхгүй хүнд хариулах эсэхийг 8.5-р тестээр шалгана. Ажиллахгүй бол `pages_messaging`-ийн Advanced Access-ийг App Review-гээр авна. Үүнд хэдэн өдрөөс хэдэн долоо хоног зарцуулагдаж, Business Verification шаардагдаж магадгүй.
- **Хүсэлтүүд хүснэгтэд хадгалагдахгүй.** Утасны дугаарууд Telegram болон пэйжийн Messenger inbox-д л үлдэнэ. Жагсаалт хэлбэрээр хадгалах бол хадгалах сан (Supabase/KV) нэмэх шаардлагатай.
- **Дугаараа эхэлж өгвөл чиглэл «тодорхойгүй» гарна.** Хэрэглэгч чиглэлээ хэлэхээсээ өмнө дугаараа бичвэл мэдэгдэлд чиглэл «тодорхойгүй» гэж гарна. Ажилтан утсаар тодруулна. Нэг мессежид хэд хэдэн дугаар байвал эхнийхийг авна.
- **Ажилтан орж ирэхэд бот өөрөө зогсохгүй.** Ажилтан гараар хариулсны дараа хэрэглэгч дахин бичвэл бот бас хариулна. Үүнийг засахад хадгалах сан хэрэгтэй.
- **Давхардлын хамгаалалт хагас дутуу.** Meta ижил мессежийг дахин илгээвэл давхар хариулахаас сэргийлэх хамгаалалт зөвхөн нэг серверийн санах ойд ажилладаг. Ховор тохиолдолд давхар хариулт эсвэл давхар мэдэгдэл гарч болно.
- **24 цагийн дүрэм.** Хариултыг зөвхөн хэрэглэгч бичсэн даруйд илгээдэг тул энэ дүрэмд үргэлж нийцнэ. Бот хэрэглэгч рүү өөрөө түрүүлж бичихгүй.
